Start a guyb session for the project in the current directory.

0. If the session started in the projects root (even if the working directory has since moved into a project) rather than a project (see "Session at the projects root" in the playbook): follow the `guyb:launch` skill (setup check, project list and picker, or "$ARGUMENTS" if it names a project, then open it in a new tab and tell the user to switch tabs) and stop. Skip this step if the user said to work here.

1. In parallel:
   - Run the read-only briefing script (no agent): PowerShell `pwsh -NoProfile -File "<dir>/brief.ps1" -Dir "<project folder>"` (use `powershell` if `pwsh` is missing), bash `bash "<dir>/brief.sh" "<project folder>"`. `<dir>` is `${CLAUDE_PLUGIN_ROOT}/skills/start`, then `<repo>/plugins/guyb/skills/start` (repo from `~/.claude/plugins/known_marketplaces.json`, `guyb.source.path`). On Windows use `brief.ps1`; strip any trailing `\` or `/` from the folder. It prints ~30 lines of plain text: branch and ahead/behind, uncommitted files, last 5 commits, open PRs, STATE.md next up / open issues, unfinished runs, open questions, the `max parallel` agent cap (optional `max_parallel: N` override in `.claude/CLAUDE.md` or `~/.claude/guyb/profile.md`), and whether `.claude/guyb/pipeline/` is gitignored. It may also print a `plugin: X installed, Y available - run: ...` line (guyb is outdated), `STATE.md drift: PR #N is MERGED - update STATE.md` lines, `env: ...` lines for toolchain gaps, a `migrate:` line (guyb files still at the legacy `.claude/STATE.md` / `.claude/pipeline/`), an `overdue:` line (unfinished runs or open questions older than `cleanup_days`), a `cleanup:` line (guyb files over their size limits or with stale scratch files), and a `warn:` line (`.gitignore` ignores all of `.claude/`); surface all of them to the user, and offer to fix the STATE.md drift. The size and age limits default to `cleanup_claude_md_lines: 200`, `cleanup_state_lines: 300`, `cleanup_rows: 200`, `cleanup_days: 14` and are overridable like `max_parallel`. Brief from that output. `guyb:session-tracker` is only for **end** mode and "what changed" deep dives.
   - Check that `~/.claude/guyb/profile.md` exists. If not, mention once that `/guyb:setup` configures git hosting and cloud logins (don't block on it).
   - Check whether `.claude/CLAUDE.md` exists. If it doesn't, read the project (README, package files, Makefile, CI, infra folders) and draft one with: what the project is, stack, git host, run/test/build/deploy commands, cloud provider + profile/project/subscription + region if cloud usage is detected (otherwise a placeholder), a `## Credentials` section listing the env var *names* the code uses, and conventions you observe. Show the draft and write it only after the user OKs it.
   - If the project is a git repo and `.gitignore` doesn't ignore `.claude/guyb/pipeline/` (or `.claude/`), append `.claude/guyb/pipeline/` (create `.gitignore` if missing) without asking, and mention it in one line of the briefing. Never add `.claude/guyb/STATE.md`: it is meant to be committed. If `.gitignore` ignores all of `.claude/`, leave it and pass on the script's `warn:` line.
   - **Migrate** (on a `migrate:` line): guyb files moved from `.claude/STATE.md` and `.claude/pipeline/` to `.claude/guyb/`. Offer the move; nothing moves without consent, and only when no run is `running`/`queued`. Declining is fine: the legacy paths (and a guyb-owned legacy STATE.md) stay in use, and writers keep updating that legacy file.
     - Ownership: `.claude/STATE.md` may belong to another tool. It is guyb's only if it contains the line `<!-- guyb:state -->`, or (legacy file without marker) has all four headings (any level, case-insensitive) `Next up`, `Open issues`, `Decisions`, `Recent changes`. If it is not guyb's or you are unsure: never move, edit or read it as guyb state; leave it untouched and create a fresh `.claude/guyb/STATE.md` (with `<!-- guyb:state -->` on line 1) when state is first recorded.
     - On consent: create `.claude/guyb/`. STATE.md (guyb-owned only), if the new file is absent: `git mv` when tracked (`git ls-files --error-unmatch`), else a plain move. pipeline/: if the new dir is absent, move the whole dir; else move only entries whose target does not exist and leave the rest. Never overwrite, never merge files automatically; for each conflict show both files' sizes and first lines and let the user decide.
     - Then in `.gitignore` replace a `.claude/pipeline/` line with `.claude/guyb/pipeline/` (or append it); remove the legacy dir only if empty; offer to update old-path mentions in the project's `.claude/CLAUDE.md`. If the moved STATE.md lacks the marker, add `<!-- guyb:state -->` as line 1. Leave changes uncommitted (the next ship commits them).
   - **Cleanup** (`overdue:` and `cleanup:` lines): act only on consent, never auto-delete or auto-archive; overdue items come first.
     - `overdue:` (unfinished registry rows or open questions older than `cleanup_days`): ask per item, with AskUserQuestion, whether it is still worth doing (keep and prioritize it). If not, ask whether it is OK to drop it (registry status `dropped` + archive row, or question status `dropped`), per `guyb:pipeline` `## Cleanup`.
     - `cleanup:` items, one line in the briefing, then per item: pipeline files and registry/question rows -> `guyb:pipeline` `## Cleanup`; STATE.md -> `guyb:session-tracker` condense mode; CLAUDE.md -> you propose specific trims (stale or duplicate sections) and the user approves each.
   - Credentials check (names only, never values): compare env vars the code references (or `.env.example`) with names present in `.env`, and confirm `.env` is gitignored.
   - Environment check: the script's `env:` lines (printed only when python, node, a package manager, or docker is missing or mismatched). Surface in one line and offer `/guyb:env`; never install from start.
   - Logo offer: if the project has no icon/logo (no `docs/icon.*`, `docs/logo*`, `logo.*`, `icon.*`, `assets/logo*`, and no image in the README header) and `.claude/CLAUDE.md` has no `logo: declined` line, end the briefing with one line: `No logo yet - want one? guyb:brand-designer proposes 3-5 options.` Never block on it. If the user declines, append `logo: declined` under a `## Preferences` heading in `.claude/CLAUDE.md` (small inline edit, only if the file exists). Skip it when a task was given in "$ARGUMENTS" and for non-project folders.
   - Load `guyb:pipeline`. From the script output: runs left `running` or `queued` from an earlier session (their agents are gone; mark them `stopped` and read their progress files for what was done). Note its open questions too.
2. Present a short briefing: project name, status, uncommitted work, open PRs/MRs, next up (from STATE.md), unfinished runs from last time, open questions from agents (ask them right after the briefing), and any missing credentials (offer `/guyb:creds` to fix them).
3. If a task was given ("$ARGUMENTS"), restate it and run it through **Intake** in the playbook (architect assesses, then plan + questions to the user). Otherwise list the suggested next steps (from STATE.md and the briefing), numbered, each with the agent that would do it, and ask which to do.
4. Whatever the user picks or asks for later goes through **Intake** unless it's small, and approved plans follow **Delegation is the default**: todo list with run IDs and waves, registry rows, then launch the agents. The orchestrator does not implement steps itself.
